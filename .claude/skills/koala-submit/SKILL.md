## Arguments

The skill is invoked with optional arguments in this format:

```
/koala-submit [config_yaml] [options]
```

Parse the arguments and user message to determine:

| Parameter | How to determine | Default |
|-----------|-----------------|---------|
| `config_yaml` | First `.yaml` path in args, or infer from context (e.g. "shape smoke" → `shape_smoke_1gpu.yaml`) | Ask user |
| `mode` | "normal" / "8卡" / "正式" → normal; "debug" / "调试" → debug | `debug` |
| `gpus` | Number mentioned, or 8 for normal mode | 1 for debug, 8 for normal |
| `job_name` | Explicit name, or auto-generate from config (e.g. `shape-smoke`) | Auto |
| `nodes` | Explicit `-n N` | 1 |

Available configs in `examples/opd/lora/trellis2/`:
- `shape_smoke_1gpu.yaml` — shape stage smoke test (1 GPU)
- `tex_smoke_1gpu.yaml` — tex stage smoke test (1 GPU)
- `shape_self_distill.yaml` — shape self-distillation (8 GPU normal)
- `tex_self_distill.yaml` — tex self-distillation (8 GPU normal)
- `dense_self_distill.yaml` — dense self-distillation (8 GPU normal)

## Execution Steps

### Step 1: Determine parameters and set shell variables

Parse the user's message and args to fill in all parameters. If the config yaml
is ambiguous or missing, ask the user. For everything else, use sensible defaults.

Auto-generate job name from config: strip `.yaml`, replace `_` with `-`, prepend
`ericzyma-`. Validate the name does NOT contain "debug" or "normal" (Koala CLI
reserved words that cause submission failure).

Set all variables upfront — Steps 3-5 reference them:

```bash
CONFIG_YAML="<resolved from user input>"
MODE="<normal or debug>"
GPUS=<1 for debug, 8 for normal>
NODES=<default 1>
JOB_NAME="ericzyma-<auto-generated, must not contain 'debug' or 'normal'>"
S3="s3://arcwm-code-us-west-2/ericzyma/flow-factory"  # fixed for this project
```

### Step 2: Verify environment tokens

Check that required tokens are set in the local shell:

```bash
echo "s5cmd: $(command -v s5cmd &>/dev/null && echo 'ok' || echo 'MISSING — brew install s5cmd')"
echo "WANDB_API_KEY: $([ -n "$WANDB_API_KEY" ] && echo 'set' || echo 'MISSING')"
echo "HF_TOKEN: $([ -n "$HF_TOKEN" ] && echo 'set' || echo 'MISSING')"
```

- **s5cmd**: Required for fast S3 sync (Step 4). If missing, install: `brew install s5cmd`.
- **WANDB_API_KEY**: Koala v1.6.0+ auto-injects this into the container.
  `setup_koala.sh` checks it — if empty, sets `WANDB_MODE=disabled` and training
  silently skips wandb logging. If the user asks for wandb ("记得带wandb", "要wandb")
  and the key is missing, **stop and warn** before submitting.
- **HF_TOKEN**: Required for gated HuggingFace models (BiRefNet). Also auto-injected
  by Koala v1.6.0+. Missing = model download fails on pod.

If both are set, proceed. If user explicitly requested wandb and key is missing, abort
with instructions: `export WANDB_API_KEY=<key>` in `~/.zshrc`.

### Step 3: Clean broken symlinks

```bash
find . -xtype l -name '*.py' -o -xtype l -path '*/.claude/*' | head -20
```

If any found, delete them (they crash s5cmd). Log what was cleaned.

### Step 4: Sync code to S3

Run in the same shell as Step 5 (so `$S3` is available for `--code`):

```bash
s5cmd sync --delete \
    --exclude '.git/*' \
    --exclude '.venv/*' \
    --exclude '*/__pycache__/*' \
    --exclude 'wandb/*' \
    --exclude 'exp/*' \
    --exclude '.claude/*' \
    --exclude '.agents/*' \
    --exclude '.scratch/*' \
    . "$S3/"
```

The S3 URI is fixed for this project. The `--code` container path MUST be
`/data/work/run_codes` to match `setup_koala.sh`'s `PROJECT_DIR`.

The `--delete` flag is critical: without it, renamed/deleted files persist on S3 and
cause import conflicts on the pod (e.g. old `training_args.py` vs new `training_args/` package).

Exclude `.agents/` and `.claude/` entirely — they contain Claude Code context
(skills, plans, sessions, Chinese-named notes) not needed on the pod, and
Chinese filenames cause `UnicodeDecodeError` in koala CLI.

### Step 5: Build and execute koala submit

**Debug mode** (default, supports SSH):
```bash
koala submit \
    --code "$S3:/data/work/run_codes" \
    -j "$JOB_NAME" \
    -y
```

Debug mode **silently ignores** the `-c` flag — pod always starts an interactive
shell regardless. After submission, tell the user to SSH in and run manually:
```
koala ssh --pod <job-name> --connect
cd /data/work/run_codes && . scripts/setup_koala.sh --fast
# 1 GPU (debug default):
/tmp/uv-venv/bin/python -u -m flow_factory.train examples/opd/lora/trellis2/<config>.yaml
# Multi-GPU:
/tmp/uv-venv/bin/accelerate launch --config_file config/accelerate_configs/multi_gpu.yaml -m flow_factory.train examples/opd/lora/trellis2/<config>.yaml
```

**Normal mode** (production training, no SSH):
```bash
koala submit \
    -m normal \
    -g $GPUS \
    -n $NODES \
    --s3-log \
    --code "$S3:/data/work/run_codes" \
    -j "$JOB_NAME" \
    -y \
    -c "cd /data/work/run_codes && . scripts/setup_koala.sh && /tmp/uv-venv/bin/accelerate launch --config_file config/accelerate_configs/multi_gpu.yaml -m flow_factory.train examples/opd/lora/trellis2/$CONFIG_YAML"
```

Critical rules (violations cause job failure):
- **Never** specify `--image` (default ECR only, custom images cause PodInitializing hang)
- **Always** use `--s3-log` for normal mode (pod logs vanish after reclamation)
- **Always** use `accelerate launch --config_file config/accelerate_configs/multi_gpu.yaml -m flow_factory.train`
  as entry point. `flow_factory.train` does NOT call accelerate internally — it must be
  launched BY accelerate for multi-GPU. Without this, `Accelerator()` sees world_size=1.
  (NOT `ff-train` or `uv run` — both trigger uv re-resolve which breaks torch/NCCL)
- **Always** use `. scripts/setup_koala.sh` (source, not `bash`) so exports propagate
- Container path must be `/data/work/run_codes` (hardcoded in setup_koala.sh)
- Add `-y` to skip confirmation prompt (Claude can't interact with it)

**If submission fails:**
- "job-name cannot contain 'debug' or 'normal'" → strip reserved words from name, retry
- "quota authorization expired" → informational only, submit proceeds with defaults
- s5cmd sync failure → check for broken symlinks (Step 3), retry

### Step 6: Report result

After submission, report:
- Job name (for `koala logs <name>` / `koala get <name>`)
- Mode (debug/normal), GPU count, config used
- **Wandb status**: WANDB_API_KEY detected → enabled; missing → disabled
- For debug: `koala ssh --pod <job-name> --connect`, then run with `python -u` (unbuffered stdout).
  Alternative: `nohup ... > /tmp/train.log 2>&1 &` + `tail -f /tmp/train.log`
- For normal: `koala logs <job-name>` or
  `s5cmd cat "s3://arcwm-code-us-west-2/ericzyma/.koala-logs/<job-name>/*" | tail -100`

**If job is stuck (PodInitializing > 5 min):**
- `koala delete <job-name>` (WITHOUT `--force`) — auto-blacklists node only if genuinely stuck
- Only use `--force` if normal delete hangs 10+ seconds
- `--force` blacklists the node for 12h — never chain `delete --force && submit` in a loop
  (can blacklist every node in the cluster)
- Check blacklist: `koala nodes list`; undo: `koala nodes unblock <node>`
